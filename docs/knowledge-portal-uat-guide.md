# 知識營運介面 UAT 操作指引

本文件供證券團隊（非 IT 人員）進行**受控使用者驗收測試（UAT）**。  
測試目標是確認：新增、匯入、送審、退回、發布等日常流程是否直覺、用語是否易懂、權限是否符合職責分離。

---

## 1. 測試目的

| 項目 | 說明 |
|------|------|
| 驗收範圍 | 知識營運介面（Knowledge Operations Portal） |
| 不在範圍 | Teams 聊天機器人、Playground、基礎設施部署 |
| 成功標準 | 五位測試人員（或五種角色）各完成一輪核心任務，且無「無法理解下一步」或「誤操作無提示」的阻擋性問題 |

---

## 2. 測試環境

### 2.1 進入方式

- **網址**：由 IT 提供（本機開發預設為 `http://localhost:8090/`）
- **登入**：依貴司 Entra ID / 測試帳號設定（UAT 環境應使用正式身分，**不要**使用 Demo 身分切換）

### 2.2 環境設定（IT 確認）

UAT 應使用 **正式治理設定（GOVERNED）**：

| 設定 | UAT 預期 |
|------|----------|
| 環境標籤 | 頁面顯示「正式環境」 |
| Demo 橫幅 | **不應**出現「DEMO MODE」 |
| 送審前測試題 | 至少 **3 題**問答測試 |
| 審核者自審 | **不允許**（審核者不可核准自己送審的文件） |

若看到「Demo 環境」或「DEMO MODE」，請先聯繫 IT，不要開始 UAT。

### 2.3 測試前準備

- 使用 **Chrome 或 Edge** 最新版
- 準備一支可匯入的 Markdown 測試文件（見任務 B 範本）
- 每完成一個任務，在回饋表記錄：是否順利、卡在哪一步、用語是否看不懂

## 3. 角色與權限

### 3.1 角色說明

| 角色 | 介面顯示名稱 | 主要工作 |
|------|-------------|----------|
| CONTRIBUTOR | 知識貢獻者 | 建立／編輯草稿、送審 |
| REVIEWER | 知識審核者 | 審核待審文件、核准或退回 |
| MANAGER | 知識管理者 | 發布正式版本、監控待辦 |
| AUDITOR | 稽核人員 | **僅**查閱稽核紀錄（唯讀） |
| PLATFORM | 平台管理者 | 與管理者類似（IT 維運用，UAT 可略） |

### 3.2 導覽列可見性

| 導覽項目 | 貢獻者 | 審核者 | 管理者 | 稽核者 |
|----------|:------:|:------:|:------:|:------:|
| 我的工作 | ✓ | ✓ | ✓ | ✓ |
| 知識庫 | ✓ | ✓ | ✓ | ✓ |
| 待審核 | — | ✓ | ✓ | — |
| 稽核紀錄 | — | — | ✓ | ✓ |

**預期**：貢獻者與審核者**看不到**「稽核紀錄」；稽核者**看不到**「待審核」。

### 3.3 首頁導向

| 角色 | 登入後預設頁面 |
|------|----------------|
| 知識貢獻者 | 我的工作 |
| 知識審核者 | 待審核 |
| 知識管理者 | 我的工作 |
| 稽核人員 | 稽核紀錄 |

## 4. 核心 UAT 任務（必做）

建議依序完成 **A → E**，模擬一份文件從建立到發布的完整生命週期。  
可指派不同人員扮演不同角色，或使用 IT 提供的測試帳號輪流操作。

---

### 任務 A：新增知識文件

**角色**：知識貢獻者  
**目的**：確認三步驟建立流程是否易懂

#### 操作步驟

1. 點選「知識庫」→「新增文件」（或從工作區進入新增流程）
2. **步驟 1 · 基本資料**：填寫標題、摘要、擁有單位、分類
3. **步驟 2 · 治理與適用**：填寫生效日、下次檢視日、變更原因；適用對象選「全體員工」
4. **步驟 3 · 正文內容**：撰寫 Markdown 正文（至少一個標題與一段說明）
5. 點選「建立草稿」

#### 預期結果

| 檢查項 | 預期 |
|--------|------|
| 建立成功 | 顯示「草稿已建立」，進入文件「內容與附件」分頁 |
| 文件狀態 | 顯示「草稿」 |
| 下一步提示 | 工作區或概覽分頁有明確的「送審」或「編輯草稿」指引 |
| 步驟指示 | 上方三步驟指示清楚，目前步驟有標示 |

#### 回饋記錄

- [ ] 能否不詢問 IT 獨立完成？
- [ ] 哪個欄位名稱仍看不懂？

---

### 任務 B：匯入「特定群組」文件

**角色**：知識貢獻者  
**目的**：確認匯入不會把受限文件誤設為「全體員工」

#### 測試用 Markdown 範本

將以下內容存成 `uat-restricted-policy.md` 後匯入：

```markdown
---
title: UAT 受限政策範例
owner: IT Service Desk
effectiveDate: 2026-01-01
reviewDate: 2026-12-31
audience:
  - securities-ops
  - branch-managers
---

# UAT 受限政策範例

本文件僅供特定群組查閱，UAT 測試用。
```

#### 操作步驟

1. 進入「新增知識文件」
2. **步驟 1**：點選「匯入文件」，選擇上述 `.md` 檔
3. 確認匯入提示（應提及已保留特定群組設定）
4. 進入 **步驟 2 · 治理與適用**
5. 確認「適用對象」為「特定群組」，且群組欄位顯示 `securities-ops, branch-managers`
6. 完成步驟 3 並建立草稿

#### 預期結果

| 檢查項 | 預期 |
|--------|------|
| 匯入後適用對象 | **特定群組**（不是全體員工） |
| 群組欄位 | 包含 `securities-ops` 與 `branch-managers` |
| 建立成功 | 草稿建立成功，內容與匯入正文一致 |

#### 回饋記錄

- [ ] 匯入後是否曾誤顯示「全體員工」？
- [ ] 群組欄位是否直覺？

---

### 任務 C：送審

**角色**：知識貢獻者（操作任務 A 或 B 建立的草稿）  
**目的**：確認送審前檢查與狀態轉換

#### 操作步驟

1. 開啟任務 B 建立的草稿（或任務 A 的文件）
2. 進入「問答測試」分頁
3. 新增 **至少 3 題**測試問題（例如：「這份政策適用對象是誰？」）
4. （選做）對每題點「執行」，確認測試結果
5. 回到「概覽」或工作區，點選「送審」
6. 在確認對話框中確認送審

#### 預期結果

| 檢查項 | 預期 |
|--------|------|
| 測試題不足 | 若少於 3 題，送審應被阻擋並有明確提示 |
| 送審成功 | 顯示「已送審」 |
| 文件狀態 | 變更為「待審核」 |
| 待審清單 | 審核者可在「待審核」看到此文件 |

#### 回饋記錄

- [ ] 是否清楚知道要先建立測試題？
- [ ] 送審確認訊息是否足夠？

---

### 任務 D：退回修改

**角色**：知識審核者  
**目的**：確認審核工作區與退回流程

#### 操作步驟

1. 以審核者身分登入，進入「待審核」
2. 點選任務 C 送審的文件，進入「審核工作」分頁
3. 檢閱以下區塊：
   - 送審資訊（送審者、理由）
   - 適用範圍變更提醒（若與正式版不同）
   - 品質檢查、問答測試結果
   - **內容變更摘要**（綠色新增、紅色刪除）
   - 正式版／草稿並排全文
4. 在「審核決策」區點選「退回修改」
5. 填寫審核意見（例如：「請補充適用對象說明」）並確認

#### 預期結果

| 檢查項 | 預期 |
|--------|------|
| 審核分頁 | 資訊完整，不需切換多個無關頁面才能完成決策 |
| 決策按鈕 | **僅在審核工作分頁底部**出現（右側工作區不重複顯示核准／退回） |
| 退回成功 | 顯示「已退回修改」 |
| 文件狀態 | 變更為「待修正」 |
| 貢獻者視角 | 貢獻者「我的工作」可看到「被退回內容」 |

#### 回饋記錄

- [ ] 內容變更摘要是否有助理解？
- [ ] 並排檢視在您的螢幕上是否可讀？（請註明桌面／手機）

---

### 任務 E：修正後核准與發布

**角色**：知識貢獻者 → 知識審核者 → 知識管理者  
**目的**：完成完整閉環

#### 操作步驟（貢獻者）

1. 以貢獻者身分開啟被退回的文件
2. 依審核意見修改正文或摘要
3. 儲存草稿後再次送審

#### 操作步驟（審核者）

4. 以審核者身分進入「審核工作」
5. 確認修正內容後，點選「核准」並填寫審核意見

#### 操作步驟（管理者）

6. 以管理者身分開啟該文件
7. 確認狀態為「已核准」
8. 點選「發布正式版本」並確認

#### 預期結果

| 檢查項 | 預期 |
|--------|------|
| 核准後狀態 | 「已核准」 |
| 發布成功 | 顯示「發布成功」 |
| 發布後狀態 | 「已發布」 |
| 工作區提示 | 管理者可看到「已發布至 Teams 知識庫」類似說明 |
| 貢獻者 | 不可發布（無發布按鈕） |
| 審核者 | 不可發布（無發布按鈕） |

#### 回饋記錄

- [ ] 核准 → 發布兩步是否清楚？
- [ ] 是否曾找不到「下一步」該做什麼？

## 5. 補充驗證（選做）

### 5.1 稽核紀錄（稽核者）

**角色**：稽核人員

1. 登入後應直接進入「稽核紀錄」
2. 確認可看到任務 A–E 產生的操作（建立、送審、核准、發布等）
3. 切換為貢獻者帳號，確認**看不到**「稽核紀錄」導覽，且無法存取稽核 API

**預期**：職責分離正確；稽核者僅能查閱，不能編輯或審核。

### 5.2 無障礙（選做）

- 按 `Tab` 可聚焦「跳至主要內容」連結
- 文件分頁可用方向鍵、`Home`、`End` 切換
- 系統設定「減少動態效果」時，載入動畫應停止閃爍

### 5.3 手機版（選做）

- 審核頁「正式版／草稿」並排應在窄螢幕改為**上下單欄**
- 主要按鈕仍可點選，文字可讀

## 7. 常見問題

**Q：為什麼送審按鈕無法點？**  
A：正式環境需至少 3 題問答測試。請到「問答測試」分頁新增。

**Q：我核准不了自己送審的文件？**  
A：正式環境不允許自審，請換另一位審核者操作。

**Q：匯入後變成「全體員工」？**  
A：UAT 版本已修正。若仍發生，請記錄匯入檔案的 `audience` 區塊並回報 IT。

**Q：找不到稽核紀錄？**  
A：僅管理者與稽核者可見；貢獻者與審核者依設計看不到。

**Q：發布後 Teams 會立刻更新嗎？**  
A：發布會寫入知識庫 release；Teams 端更新時機依 Agent 部署設定，UAT 以 Portal 狀態「已發布」為準。

## 8. 問題回報

| 嚴重度 | 定義 | 範例 |
|--------|------|------|
| **阻擋** | 無法完成任務 | 送審後狀態未變、按鈕無反應 |
| **重大** | 可 workaround | 需 IT 解釋才能繼續 |
| **輕微** | 用語或排版 | 欄位名稱太技術、手機间距 |

回報請附上：角色、步驟、截圖、文件標題、發生時間。
