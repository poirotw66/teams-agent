## 1. 重構目標

讓BU登入後知道今天要處理什麼；從問題查證、內容修正到品質驗收能沿同一任務往下走。把功能完整度保留下來，減少重複入口、整頁說明、無關欄位及跨頁重新選條件。

設計方向：穩定、清楚、低干擾的企業工作介面。採用專案design-taste-frontend skill的現況盤點、品牌保留、層級與狀態一致性原則；該skill主要面向展示網站，巨大標題、展示動畫、禁止長表格等規則不適用本後臺。

設計參數提案：DESIGN_VARIANCE=3、MOTION_INTENSITY=1、VISUAL_DENSITY=6。這是目標方向，不是目前畫面的實測評分。

首要成果不是換色，而是下列任務可順暢完成：
1. 找到我的待辦並處理一個負評／無答案案件。
2. 更新FAQ或文件，完成審核並確認Agent已使用新版本。
3. 找到一則對話，理解回答依據與處理結果。
4. 找到需要改善的高頻問題，追到案件或內容。
5. 比較候選與基準品質，確認退步原因及下一步。

## 3. 新資訊架構提案

不再要求BU切換「知識營運／AI管理／平台管理」才能完成同一件事。側欄使用固定位置與單一名稱，依capability顯示可用入口；權限由後端決定，不以隱藏導覽取代授權。

| 一級入口 | 子頁／頁籤 | 主要使用者 |
|---|---|---|
| 我的工作 | 待我處理／待我審核／追蹤中；有權限者切換團隊 | BU、Knowledge Admin、Service Owner |
| 改善案件 | 案件／回饋事件／知識缺口 | BU、Service Owner |
| 知識內容 | 文件／FAQ；內容審核／發布與更新作子頁 | BU、Knowledge Admin |
| 對話紀錄 | 對話查詢、單一對話詳情 | BU、Service Owner |
| 品質驗收 | 驗收題庫／執行驗收／驗收結果 | BU、AI Admin |
| 營運分析 | 總覽／問題分析／內容成效／成本 | Service Owner、Analyst |
| 系統管理（獨立分組） | AI設定、執行與告警、權限與資料治理 | AI Admin、System Admin、Auditor |

全域搜尋放在頂部搜尋欄，結果仍有可分享的完整頁面；不佔據平台管理的一般功能位置。

角色預設首頁：BU／Knowledge Admin到我的工作，Analyst到營運分析，Auditor到稽核，AI Admin到品質驗收或其選定首頁。沒有首頁資料權限時轉第一個有權頁面；不可因此擴張角色能力。

「我的工作」統一顯示任務摘要但不合併領域狀態。文件審核、案件指派、Golden題目審核各保留原責任與審核規則。沒有指派／審核權限的資料，不虛构成「我的待辦」。

## 5. 六個關鍵頁面設計

### 5.1 我的工作：先做事，再看數據

首屏：標題＋責任範圍 → 待處理／待審核／追蹤中三個計數選項 → 任務清單。預設不加入整排對話量、Token、索引狀態卡片。

清單欄位：任務、類型、需要做什麼、負責人、等待時間、狀態。每列一個主要動作「處理／審核／查看結果」。其他操作放更多。

未指派、逾期、退回可作快速篩選；若系統沒有SLA，不把等待時間自行算成逾期。資料源失敗顯示「暫無法取得文件待審」，不能顯示0件。

### 5.2 改善案件：查證與下一步同頁

案件清單：問題摘要、影響／頻率、Owner、狀態、最近更新；常用篩選僅搜尋、狀態、負責人，其他展開。回饋事件與知識缺口各有獨立篩選、分頁與統計。

案件詳情使用完整頁面，主區顯示問題、相關對話、答案與依據；右側顯示指派、狀態、下一步及事件歷程。小螢幕改上下區塊。

按案件實際狀態提供「修正知識」「加入驗收題」「查看驗收結果」等動作；沒有必要輸入／權限時説明原因。FAQ／文件選擇在建立當下提供兩句差異提示，完整政策不占常駐主區。

不將「更新內容」直接等同「案件完成」；保留發布、生效、驗收、觀察與結案依據。

### 5.3 知識內容：清單直接開始工作

文件／FAQ兩個平行頁籤，共用搜尋、狀態、Owner、表格樣式，但各自保留必需欄位與權限。主動作隨頁籤為「上傳文件」或「新增FAQ」，不要讓使用者每次經過中轉頁。

文件欄位：標題、Owner、內容審核狀態、Agent使用版本／更新狀態、更新時間。FAQ欄位：問題、Owner、啟用狀態、使用版本、更新時間。

詳情頁籤：內容／版本與發布／使用成效／驗收題與結果／異動紀錄。預設只請求目前頁籤資料。編輯使用完整頁面、固定儲存動作與離開保護；短確認才用dialog。

必須分開顯示「內容已核准」「已發布」「Agent使用中」「索引失敗」，不可為了簡潔合成含混綠色「完成」。狀態可用短句表示，如「新版已發布，Agent仍使用上一版」。

### 5.4 對話紀錄：可讀的回答證據

清單以時間、遮罩使用者、提問摘要、是否解決／回饋為主；Issue、模型與ID收進可選欄。詳情主區是對話時間線，側區為目前回合的引用、處理方式與派工結果。

右側來源随選取回合更新，不把整段對話所有引用混成一份。工具／原始事件／correlation ID放技術詳情。必要時建立品質案件或驗收候選，沿用同一conversation／turn來源。

### 5.5 品質驗收：先看退步，再看分數

沿用Golden spec的題庫／執行／結果三頁籤。題庫內的題目與版本子頁支援深連結，避免所有編輯與版本維護都塞modal。

執行頁以「選題庫→比較版本→確認範圍與成本」逐步呈現；fixture／真實知識／Agent sandbox模式用可理解說明，不能藏掉模式差異。

結果首屏依序：是否可判定 → 重大失敗／新增失敗／已修復／未完成 → 逐題清單。詳情左右對照預期與實際，技術頁籤顯示證據、工具、評分與版本。

COMPLETED、品質PASS與發布核准分開顯示；HOLDOUT、人工覆核及gate細節不因UI簡化而放寬。

### 5.6 營運分析：回答「哪裡需要改善」

總覽只保留少量核心指標、趨勢與需要關注的問題；卡片每個指標可下鑽且帶完整期間／Owner範圍。

問題分析以排名表為主；選問題進完整詳情，整合趨勢、處理方式、引用內容、相關回饋與案件。把「路由」改為「處理方式」，把「來源」改為「回答依據」，避免同義或工程詞。

由分析回到處理時保留問題／期間／範圍；匯出严格使用目前查詢。成本与用量獨立頁籤，不與品質指標混算總分。

## 6. 常用任務連續性契約

| 任務 | 預期路徑 | 必須保留的資訊 |
|---|---|---|
| 負評修正 | 我的工作→案件→對話／依據→修正內容→驗收→回案件 | caseId、conversation／turn、來源及版本、returnTo |
| 更新文件 | 知識內容→編輯→送審→發布／更新→確認Agent版本 | documentId、versionId、scope、jobId；各步不同狀態 |
| 查證回答 | 對話清單→詳情→選回合→引用原文 | 期間、遮罩使用者條件、頁碼／cursor、scroll、turnId |
| 高頻問題改善 | 營運分析→問題→負評→案件 | issueTypeId、期間、Owner；不可悄悄恢復30天 |
| Golden驗收 | 內容／案件→驗收候選→題庫版本→run→結果 | sourceRef、case revision、set version、target manifest |
| 審核與例外 | 我的工作→待審詳情→差異／結果→核准或退回 | 審核人scope、version／etag、理由；不可用批次略過必要檢查 |

URL保存安全且可分享的view／tab／物件識別及期間；不得把對話原文、姓名、token或受限答案寫入URL。敏感查詢依既有合規儲存方式保存。returnTo只允許站內已登錄路由。

返回、重新整理、開新分頁、複製連結都能定位同一頁籤／對象；未儲存編輯先處理離開提示，不先切換工作區或更新側欄。

## 7. 視覺與共用元件規範

保留現有品牌、藍色主色與淺灰白底；初版沿用原生JS及既有tokens，不因重新設計強制搬到React／Next或導入大型元件套件。這是本專案設計系統，不宣稱已採用Fluent UI官方元件。

| 元素 | 建議規格／原則 |
|---|---|
| 頁殼 | 一個頂列＋固定側欄；頁面正文僅一個標題，避免portal再畫第二套殼層 |
| 字體 | 保留現有字體資產，優先驗證繁中fallback；標題24px、內文14–16px、表格14px為起始值，依實畫微調 |
| 間距 | 4／8／12／16／24／32尺度；工作頁24px主間距，不使用展示頁的大面積留白 |
| 容器 | 淺灰底＋白色主內容，分隔線優先；不把每個區塊再套一張卡片；陰影主要用於浮層 |
| 圓角 | 控制項6–8px、浮層8–12px，表格不做大圓角多層外框 |
| 色彩 | 藍色為主要動作；紅／黃／綠保留語意並搭文字／圖示，不能用單一品牌色取代所有狀態 |
| 按鈕 | 每個任務區一個主動作，次動作用中性樣式；高風險動作具體描述對象、版本與結果 |
| 篩選 | 常用欄位常駐、進階收合；顯示作用範圍、套用中的條件與清除動作，不能只把欄位藏掉 |
| 表格 | 固定標題列、可排序、文字截斷可展開、可選欄位；避免逐列大量按鈕及全頁橫向滾動 |
| 詳情 | 長閱讀／編輯用完整頁面；短預覽用drawer；確認用dialog；不形成多層modal |
| 動態 | 100–160ms狀態轉換，不用彈跳／發光吸引注意；支援reduced motion |
| 狀態 | 首次loading用匹配版型骨架；更新保留內容；空白、無權、無結果、部分失敗、過期資料分開 |

共用元件優先整理：AppShell、PageHeader、FilterBar、DataTable、StatusBadge、DetailLayout、ActionBar、SourceReference、JobProgress、Empty／ErrorState。先檢查既有analyticsUi／modal／period可擴充之處，不再平行新增第三套樣式。

主要使用桌機，驗證1440、1280、1024寬度與200%縮放；窄螢幕側欄收合、詳情上下排列，只有表格區可橫捲。鍵盤焦點、label、dialog焦點還原、狀態文字及對比列入驗收，不能只看截圖。

## 8. 資料新鮮度與效能UX

- 每個資料區顯示最後更新時間；背景工作顯示排隊／執行／完成／失敗與下一步。
- 預設僅讀當前頁籤；品質頁不要因未開啟的gap失敗讓案件無法使用。
- 篩選請求可取消或用request generation防止舊回應覆蓋新條件；快速切頁不得把舊資料畫到新頁。
- 背景刷新不改捲動位置、不清除輸入、不把使用者正在看的列重新跳位；有新資料時提供更新提示。
- 使用既有查詢／工作狀態機制，不為UI規劃宣稱一定需要WebSocket；輪詢間隔、退避與失敗提示集中設定。
- 首頁聚合如需新增read model，回傳各來源asOf、partialErrors、scope；跨來源不可分頁錯誤後以「總數0」掩蓋。

## 9. 工程邊界與Golden開發協作

| 工作 | UI可先處理 | 需後端／契約支持 |
|---|---|---|
| 導覽與名稱整併 | route alias、label catalog、側欄及頁籤 | 後端權限維持原capability |
| 我的工作 | 摘要版型、任務跳轉 | 可能需跨域待辦聚合、Owner／指派／待審scope与局部失敗 |
| 知識更新狀態 | 狀態短句與progress呈現 | 必須已有準確發布／active version／索引job資訊，不由前端猜測 |
| 案件到驗收 | 帶來源候選與返回連結 | Golden來源／case／set／run契約及權限 |
| 搜尋與過濾 | URL／query state一致性 | 跨來源查詢、排序、分頁與匯出語意需對齊 |

Golden開發期間先約定穩定的route／tab參數、sourceRef／returnTo及PageHeader／Table／Status介面；不要求其功能開發等待完整視覺遷移。功能完成後先驗收GE本身，再按新模板移植。不得為整併UI把正反例直接變Golden或把fixture結果改成發布通過。

新增route registry，canonical頁與歷史alias分開。舊`#/platform/issues?...`、`routes?...`及knowledgePortal subroute等保留轉址及query映射；舊連結開新分頁仍可用。不刪既有測試，先增加新架構測試，確認後更新過時預期。

## 10. 分階段實作順序

此UI波次U1～U4與Golden的GE-1～GE-4獨立，避免混用編號。

| 波次 | 範圍 | 交付與退出條件 |
|---|---|---|
| U1 資訊架構與元件基礎 | 核准側欄、全頁映射、route契約、tokens與列表／詳情原型 | 六個關鍵頁線框確認；舊URL、最小權限、返回／刷新測試；先做1個列表與1個詳情驗證再推廣 |
| U2 BU高頻工作 | 我的工作、改善案件、知識內容、對話紀錄；移除hub中轉與常駐冗長指南 | 完成負評修正與知識更新两條完整任務，審核／版本／scope無回歸 |
| U3 分析與品質驗收 | Issue／routes整合、內容成效、Golden題庫／執行／結果外觀与來源串接 | 問題下鑽期間不丟失，Golden既有驗收全部保留，退步案例能直接回到改善任務 |
| U4 管理一致性與收尾 | Prompt／模型／旗標／預算／健康／權限／保存／遮罩／稽核／搜尋 | 全頁套用共同狀態與樣式、舊入口相容、可及性與BU任務驗收完成，移除已無使用的重複樣式 |

先用feature flag切換新殼層與已遷移頁，未遷移頁維持可用，不能出現兩套主導覽同時顯示。先遷移具體任務，再移除舊入口；資料模型與正式發布不因UI切換而改變。

## 11. 驗收與量測

以下是提案目標，尚無目前基準數據；U1先用相同帳號、資料與任務測舊版，之後比較新版。

| 項目 | 驗收目標 |
|---|---|
| 任務完成率 | 找對話、處理案件、更新內容、審核、比較驗收5類任務，代表性BU無工程師口頭導引至少90%完成；樣本數與失敗案例一併報告 |
| 完成時間 | 中位數比基準縮短至少25%作改善目標；未達標回查步驟，不以改色代替成效 |
| 導覽可找性 | 常用工作由常駐入口直接找到；內容列表不再經中轉卡片；不以刪安全確認來追求點擊減少 |
| 上下文 | 返回、刷新、複製連結、開新分頁維持安全篩選與目標；未儲存內容不靜默遺失 |
| 狀態正確 | pending／failed／unknown／0／無權不同呈現；內容核准、Agent生效、Eval完成、品質通過不得混淆 |
| 權限 | Viewer、Knowledge Admin、Service Owner、AI Admin、Auditor最小scope端到端測試；各入口与直接URL一致 |
| 響應與穩定 | 在記錄好的資料量／網路／機器條件下量測；遷移頁不增加無關API請求，快速篩選無舊回應覆蓋 |
| 可及性 | 鍵盤任務、焦點還原、繁中長字、縮放、小螢幕、色彩對比及reduced motion驗證 |
| 能力保留 | 27個現有view逐一對映測試；查詢、匯出、審核、發布、回復与Audit能力不因入口整併遺失 |

正式開發前補做瀏覽器盤點：至少我的工作對應現有首頁、品質、文件／FAQ、對話、Issue、Golden六組畫面；记录首屏可操作性、滾動深度、主動作數與樣式差異。此次未完成此項，不將原始碼推論當作已實測UX缺陷。
